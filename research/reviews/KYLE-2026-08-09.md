## Severity summary

- Critical: none.
- High: one — an omitted build context bypasses `MountPolicy` by selecting the CLI's
  implicit current-directory context.
- Medium: one — explicit path checking has a symlink check/use race for a path that is
  absent or is repointed after validation.
- Low: one — `research/ALLOWLIST-AUDIT.md` now describes an older 35-command table and

## High — an omitted context reads `.` without consulting `MountPolicy`

`build` declares the context operand as `.hostBuildPath`, but also declares `min: 0`
([`Allowlist.swift:578`](../../Sources/FlotillaCore/Allowlist.swift#L578)). The validator only
calls the shape checker for operands that actually exist
([`Allowlist.swift:794`](../../Sources/FlotillaCore/Allowlist.swift#L794)). The captured CLI
help says an omitted context defaults to `.`, so absence is not “no host path”; it is an
implicit relative host path.

Concrete reproduction:

```swift
let result = Allowlist.validate(
    ["build", "--tag", "app:latest"],
    mountPolicy: .denyHostPaths
)
// result is .success, canonical argv:
// ["build", "--tag", "app:latest"]
```

Run that command with the host process working directory set to
`/Users/alice/private-project`. The CLI interprets it as:

```text
container build --tag app:latest .
```

and archives `/Users/alice/private-project` even though `.denyHostPaths` grants no host
path. The same bypass remains when `--file` is explicitly authorised:

```swift
Allowlist.validate(
    ["build", "--file", "/tmp/allowed/Dockerfile"],
    mountPolicy: .roots(["/tmp/allowed"])
)
// success; the Dockerfile is checked, but the implicit context is still the host cwd.
```

This directly contradicts the comments and tests saying an omitted operand grants no path.
It matters most on the future host peer, whose working directory is an execution detail and
not a root authorised by the requester-facing policy.

Recommendation: do not permit an omitted context at this boundary. Require one absolute
`.hostBuildPath`, or have the trusted host resolve a deliberate working directory to an
absolute path and validate that path before emitting it. Do not merely append `.`: a relative
path still cannot be checked against absolute policy roots.

## Medium — symlink resolution is not bound to execution

Existing symlinks are resolved correctly for both `--file` and the context operand. The new
test at [`AllowlistTests.swift:1065`](../../Tests/FlotillaCoreTests/AllowlistTests.swift#L1065)
creates a symlink inside a permitted root pointing outside and proves that both positions are
rejected.

The remaining gap is the acknowledged check/use race in `MountPolicy`: a nonexistent suffix
is retained lexically, and the returned canonical argv contains the original unresolved path
([`MountPolicy.swift:97`](../../Sources/FlotillaCore/MountPolicy.swift#L97),
[`MountPolicy.swift:129`](../../Sources/FlotillaCore/MountPolicy.swift#L129)). There is no
filesystem handle or resolved path tying validation to the later `Process.run()`.

Concrete reproduction, requiring write access to the permitted root during the validation →
execution window:

```text
mkdir -p /tmp/allowed
# /tmp/allowed/context does not exist yet
```

```swift
Allowlist.validate(
    ["build", "/tmp/allowed/context"],
    mountPolicy: .roots(["/tmp/allowed"])
)
// success: the deepest existing ancestor is /tmp/allowed and "context" is kept as a tail.
```

Before the validated argv is spawned:

```text
ln -s /Users/alice /tmp/allowed/context
```

The unchanged argv now makes the CLI follow the link and build `/Users/alice`. Repointing an
already-checked symlink during the same window is the equivalent race.

This is conditional, hence Medium rather than High: the attacker needs a writable permitted
root and timing or another local actor. The safest near-term rule for build inputs is to
require them to exist at validation and emit their resolved absolute paths; that narrows but
does not fully eliminate TOCTOU. A complete fix needs the execution boundary to consume a
stable filesystem object or otherwise enforce containment at use time.

## `container build` grammar: verified non-findings

Apart from the implicit context and the symlink race above, the declared grammar is at least
as strict as the captured CLI help.

`--secret`, `--output`/`-o`, `--vsock-port`, `--dns`, `--dns-domain`, `--dns-option`, and
`--dns-search` are genuinely unreachable. Long names are matched exactly; `=` is split only
after the exact name is extracted; short flags must be exactly two characters; build forbids
`--` trailing tokens; and flag parsing continues after the context operand. The regression
matrix at [`AllowlistTests.swift:1027`](../../Tests/FlotillaCoreTests/AllowlistTests.swift#L1027)
covers abbreviations, inline values, repeated occurrences, post-operand flags, the separator,
and `-o`.

Representative rejected argv:

```text
build --sec id=npm,env=NPM_TOKEN /tmp/build
build --secret=id=npm,env=NPM_TOKEN /tmp/build
build --secret id=a,env=A --secret id=b,env=B /tmp/build
build /tmp/build --output=type=local,dest=/tmp/out
build /tmp/build -- --dns=10.0.0.1
build -o type=local,dest=/tmp/out /tmp/build
```

Explicit `--file` and context operands both call `.hostBuildPath`. Explicit relative paths
(`.`, `../src`), `..` components, and URL-like values (`https://example.test/context`,
`file:///tmp/context`) are rejected because the shape requires an absolute filesystem path.
An already-existing symlink escape is rejected. A string such as
`/tmp/allowed/--secret=id=x` can be a permitted context operand, but remains one local path
token in the canonical argv and does not activate `--secret`.

## `.username` redaction: no finding

The captured shape is a JSON string at `userSetup.username`, and the rule catches compact and
pretty-printed JSON while preserving the key. It deliberately does not catch bare `user`, so
useful container runtime identities remain visible.

Concrete input:

```text
{"userSetup":{"username":"someperson"},"user":"root"}
```

Redaction removes `someperson`, preserves `"username"`, and leaves `"user":"root"`. On the
raw input, `RedactionAudit.leaks` reports `.username`; after redaction it reports none. The
detector independently repeats the same key/value envelope and agrees with the rule for the
actual captured shape ([`Redaction.swift:119`](../../Sources/FlotillaCore/Diagnostics/Redaction.swift#L119),
[`Redaction.swift:192`](../../Sources/FlotillaCore/Diagnostics/Redaction.swift#L192)).

The rule also covers `userName` and `login`, which could redact a useful service account in
some hypothetical JSON, but there is no such payload in the repository or captured fixtures.
The only demonstrated occurrence is the host identity in `machine-inspect.json`, where
redaction is correct. I therefore do not count an over-redaction finding.

## Disposition — 17 August 2026 (the app owner)

- **High** (omitted context reads `.` without consulting `MountPolicy`) — **fixed.** The context
  operand is `min: 1`. the review's reproduction is now a test, and two existing tests that asserted the
  old behaviour were corrected with it.
- **Medium** (symlink resolution not bound to execution) — **narrowed, not closed.** A build input
  must now exist when it is validated, which removes the "create something in the validation gap"
  half of the race — the review's own recommended near-term rule. Containment is checked against the
  resolved path as well as the given one, and `AppModel.buildImage` resolves the chosen folder
  before validating so the UI does not contribute a link of its own.
  **Residual, stated plainly:** repointing an object that already exists is still possible in
  principle. Closing that needs the execution boundary to hold a filesystem handle rather than a
  string, and `Process` does not offer one. Not attempted; recorded instead.
- **Low** (`ALLOWLIST-AUDIT.md` stale) — **annotated.** The audit now carries a currency note
  saying it covered 35 entries against today's 46, that all four of its defects are fixed, and
  that its conclusion about the 22 unverified plugin-backed specs still stands. The body is
  deliberately unedited: an audit records what was examined on a date, and rewriting it to match
  current code would destroy the only thing it is for.
