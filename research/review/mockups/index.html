Flotilla — UI mockups Design direction for review · native macOS 26, not a web app
6 screens

These are HTML simulations of a native Mac app: real window chrome, SF system type, vibrancy and Liquid Glass materials on the functional layer only, and AppKit-shaped controls. Nothing here reuses the melonfleet web design system. Watermelon pink is the brand tint (selection, identity, default buttons) and green means healthy — nothing else. Fake data throughout, but the shapes come from the real captured container 1.0.0 JSON.

Screens
Menu-bar popover
Anchored under a simulated macOS menu bar: rollup meters, running containers with inline stop, fleet summaries, needs-attention section, footer actions. Look for: is the popover shallow enough? Do the glyph states read?
Main window
Sidebar (Containers / Images / Volumes / Fleet / Settings) plus hosts, a sortable container table grouped by host, a selection action bar, and an inspector. Run sheet and right-click menu included. Look for: table-by-default instead of the card grid — this needs sign-off.
Container detail
Overview, Logs (streaming, with a --boot toggle), Terminal, Stats, Files, Inspect. All six tabs are clickable. Look for: which tabs are worth Phase 1 versus waiting for streaming.
Fleet
Aggregate rollup, nine host cards covering all five connection states, a per-host drill-down inspector, and the config-drift table. Look for: untrusted vs unreachable vs version-mismatch — do they read as different problems?
Settings
Six panes — General, Resources, Network, Updates, Fleet, Advanced — populated from the preferences research, including locked/managed values and the three-way reset. Look for: is this the right number of knobs? Anything missing that you'd want on day one?
First run
Seven steps: welcome, preflight checks with inline fixes, install progress with a log, empty states, add-host (Bonjour + manual), fingerprint pairing, done. Plus the changed-certificate dialog. Look for: the pairing comparison — enough to trust, without being a chore?

Every page is linked to every other page from the floating navigator at the bottom, and the Notes button opens the rationale for that screen, with the phase and priority of each idea. Auto / Light / Dark switches appearance — dark mode is a first-class pass, not an afterthought.

Brand tint, used sparingly
flesh · brand flesh deep · default button success · running online dot rind stripe system red · errors system orange · warnings

Pink is brand, selection and identity. Green is health. Pink is never an error colour — failures use the system's semantic red and orange, which is a small extension to design/branding.md (it assigns pink and green jobs but never defines an error colour). Data surfaces stay neutral, same rule as Liquid Glass: chrome and status, not content.

Control vocabulary
Buttons Bezel Default Delete… Disabled Glass cluster Run… Pull image… Segmented AllRunningStopped Switch · check · radio managed Popup · field · search 5 seconds 7443 is:runningname Status Running Stopped Restarting Exited (137) Untrusted Connecting Type SF system font at 13 px — the Mac control size, not 16 px web body copy 11 px secondary, tabular figures for counts: 14 · 21 · 6.2 GB SF Mono / Ubuntu Mono for logs, JSON, ports and fingerprints

Status is always a dot plus a distinct glyph or shape plus a word. No colour-only state anywhere, no hover-only affordances — the two accessibility failures Podman filed against themselves.

Decisions this mockup is asking you to make
  1. Table by default, cards as a toggle. This overturns the premise of design/dashboard-mockup.html: the card grid is lovely at four containers and unusable at forty. The cards survive as a view toggle.
  2. A popover rather than a menu for the menu-bar extra, which deviates from HIG's default advice under its own “too complex for a menu” exception.
  3. Sidebar shape. Four content items plus hosts plus System. Volumes stays a top-level row here; the alternative is folding it into a single System page.
  4. An error colour. Branding assigns pink and green jobs but defines no failure colour, so failures use the system red/orange and pink stays brand-only.
  5. Which detail tabs ship in Phase 1. Overview, Logs and Inspect are cheap; Terminal needs a real PTY, Stats needs streaming, Files needs container cp.
  6. Notifications exist at all — PLAN.md doesn't mention them. Five categories are proposed, error ones not disableable.
  7. Two-tier managed settings (“defaults” seed vs “locked”), which extends reference/jamf-config-profile.md's simpler “managed value wins”.

Static HTML, no frameworks, no CDNs, no network access. Shared local assets/mac.css, assets/icons.js (inline SVG sprite) and assets/app.js.
