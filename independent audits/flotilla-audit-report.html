melonfleet · Flotilla · Phase 1 local MVP

Flotilla is a real local container console with a settings UI that over-promises the fleet.

The Swift core is substantial: allowlisted CLI execution, mount policy, redaction, and 307 passing FlotillaCore tests. The macOS app already lists, runs, inspects, and mutates containers, images, volumes, networks, and machines. The audit’s main product risk is honesty: editable controls for host mode, Jamf lock, launch-at-login, and Sparkle updates persist values that nothing consumes. Security of the local argv boundary is strong; the remaining issues are PATH fallback in the terminal tab, inconsistent delete confirmation, and Phase 2 residual risk that must not ship with the current executor.

Top five issues

  1. Inert security-adjacent settings. Settings › Network exposes Client/Host/Both, listen port, Bonjour, and a Keychain identity label. There is no listener, no pairing, no Keychain identity. Launch-at-login and update toggles are the same class of defect. Gaps GAP-01, GAP-02, GAP-04, GAP-05
  2. Terminal tab undoes PATH hardening. LocalHost launches container by absolute path on purpose. TerminalTab falls back to /usr/bin/env if the two hardcoded paths are missing. Security SEC-01
  3. Delete confirmation is not one policy. Volumes/images/networks honour confirmDestructiveActions. Container context-menu Delete calls perform(.delete) directly. Bulk confirm is declared and never read. Security SEC-02, SEC-06
  4. Phase 1 UX contracts still open. Guided install and kernel remediation are explicitly out of Preflight. Volume/network inspect is allowlisted but has no CLI method or UI. Images/volumes/networks empty states have no primary action. Gaps GAP-03, GAP-06 · UI UI-03
  5. List chrome is forked. ResourceListControls exists because five copies drifted before. Containers and Machines still hand-roll the toolbar, a second Presentation enum, and embedded detail navigation. Tables show state as a colour-only dot. Redundancy RED-01 · UI UI-01

Severity policy used here

No critical current finding. Phase 2 remote transport is not implemented, which is documented future work — not a live remote attack surface. Settings that imply that surface exists today are scored High (product honesty / enterprise posture), not Critical. Residual Phase 2 host risks are grouped as SEC-12 and must gate any listener.

Cross-cutting themes

1. Controls that drive nothing

This is the failure the codebase already names in comments. confirmBulkActions, host mode, listen port, Bonjour, identity label, launch-at-login, Sparkle toggles, and containerBinaryPath persist without a runtime consumer. The project has lost this bet more than once (presentation used to be inert; ResourceListControls exists because Cards lost Copy).

2. The wire is designed in the core, absent in the app

WirePolicy, Exposure, and Q14 tests are real. RemoteHost is a comment on a protocol. Settings still offer Host mode. Treat that mismatch as a ship blocker for any build that looks like a fleet console, not as “Phase 2 will fix it.”

3. Parity that lives in five files

Volumes/Images/Networks adopted the shared list shell. Containers/Machines did not. Empty states, confirmation, presentation enums, and detail chrome therefore diverge. UI inconsistency and redundancy are the same root: no single list/detail primitive.

4. Docs lag the tree

README still says “29 tests” and “read-only ContainerCLI”. PHASE1.md repeats the read-only claim. The test suite is 307 and mutations ship. Contributors will build the wrong thing.

5. Brand tokens are good; surfaces still drift

Theme.swift correctly quotes BRAND.md and bans pink-as-error. Cards, detail panels, and sparklines still use .quaternary / .secondary / system separator, so the honeydew wash and the mockups disagree on what a card is.

Prioritized recommendations

  1. Honesty pass on Settings — this week

    Disable or annotate Host mode, listen port, Bonjour, identity label, launch-at-login, and update checks until each has a runtime consumer. Add a registry test: every user-editable key is read by production code. Wire containerBinaryPath into LocalHost or stop showing it as an override.

  2. Close the two local security seams

    Resolve the terminal binary through Preflight.locateBinary and fail closed. Centralize delete/stop/prune confirmation so every entry point reads confirmDestructiveActions / confirmBulkActions. Redact --env / --build-arg in auditDescription before any host log exists.

  3. Finish the Phase 1 UX contract users already paid for

    Guided pkg + kernel remediation (or an honest Continue-anyway preflight card). Volume/network inspect API + read-only panes. Empty-state primary actions and filtered-empty “Clear filters” on Images/Volumes/Networks. Status badge (dot + symbol + label) in tables.

  4. Collapse list/detail chrome onto the shared types

    Migrate Containers/Machines onto ResourceListControls + ResourcePresentation. Extract embedded detail navigator and inspect toolbar. One ThemedCard modifier. This is both a UI and a redundancy fix.

  5. Gate Phase 2 on the allowlist audit’s remaining policies

    Do not open a listener until process timeouts and concurrency are enforced, publish/interface policy exists, opaque driver options are default-deny over the wire, response redaction is real, and managed preferences actually load. Q14 already says timeoutHint enforces nothing today.

  6. Refresh the contract docs and add one UI test target

    Rewrite README / PHASE1.md status blocks to match August 2026. Add a small App-level test target that fails if a Settings key has no consumer, and snapshot the destructive-action coordinator.

What is working

Credit where the tree earned it. A gap list without this section would mis-rank the project.

  • Argv, not a shell. LocalHost sets process.arguments and resolves an absolute binary. Metacharacters are not interpreted by /bin/sh.
  • Allowlist is a real boundary. Default-deny specs, Unicode/control rejection, WirePolicy / Exposure, pre-substitution exposure checks after the prior security review, and a registry test that a new spec must declare exposure.
  • MountPolicy is separate from grammar. Remote+unrestricted is a precondition failure. Build contexts go through NSOpenPanel + scoped roots.
  • Support bundles fail closed. Redaction audit can refuse the bundle. Sensitive settings are dropped. No upload path. About/Privacy states no telemetry.
  • Brand Theme is documented and mostly used for tints, state colours, and dashboard charts. Wordmark is drawn, not fetched — no Google Fonts at launch.
  • 307 FlotillaCore tests including adversarial allowlist and leak-detection support-bundle tests. Linux portable core is a genuine split, not a comment.
